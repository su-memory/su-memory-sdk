# AI 代码生成自动执行规范（优化版 v2 · 可执行）

> 适用主体：Codex 及公司所有授权 AI 代码生成模型。
> 规范属性：强制自动执行规则。所有 AI 产出代码必须逐条匹配。
> 定位：本规范是 `_ai-eng-kit` 工程化体系的**质量门禁治理层**，叠加在现有四阶段流水线（需求→架构→编码→测试→质检）之上。
> 配套脚本：`risk-classify.sh`（风险定级）、`quality-gate.sh`（质量门禁）、`ai-guard.sh`（提交守卫）。

---

## 0. 与现有体系的关系

- 本规范不替代 `.ai-rules.md`（AI 宪法）与四阶段流水线，而是为其**补充分级路由 + 量化门禁**。
- 优先级：人类当次显式指令 > `.ai-rules.md` > 本规范 > profile 约定。
- 风险定级是本规范的核心开关，决定后续走哪条通路（L0/L1/L2）。

---

## 1. 代码风险分级（AI 自动定级 + 保守兜底）

### 1.0 定级原则（关键修正：解决"谁来定级"盲点）
- **AI 不做自评定级**（LLM 系统性低估自产代码风险）。
- 默认按 **L2（最高风险）**保守兜底，除非满足 §1.1 的 L0 显式特征。
- 定级由 `risk-classify.sh` 基于**文件路径 + import + 调用图 + 关键字**静态推断，输出可解释依据。
- 人工可在 `.ai-requirement.md` 中显式标注 `risk: L0|L1|L2` 覆盖自动定级（覆盖需在 PR 说明理由）。

### 1.1 L0 低风险（免逐行审核，但非"零人工保证"）

> ⚠️ 诚实化声明（v2 修正）：
> 自动化门禁（ruff/radon/bandit/覆盖率）是**静态 lint + 已知坏模式匹配**，**不做路径敏感的缺陷分析**，
> 无法发现逻辑缺陷（如除零、None 崩溃、边界错误）。逻辑正确性的唯一保证是**测试用例覆盖到这些路径**。
> 因此"L0 免逐行审核"成立的前提是：**变异测试（mutation testing）分数达标**——
> 变异测试会自动注入缺陷（如把 `>` 改成 `>=`、把 `+` 改成 `-`），若测试套件抓不到，说明测试覆盖有洞。
> 仅当变异分数 ≥ 80% 时，L0 才可免逐行审核；否则仍需抽审或补测试。
> 禁止把门禁当作"逻辑正确性的唯一判定依据"——那是过度声明。
**自动命中特征（全部满足）**：
- 文件路径仅含 `utils/ helpers/ scripts/ migrations/ tests/` 或后缀为 `_test.py / .spec.ts`。
- 无 `import` 涉及 `payment / order / auth / user / permission / crypto / db.session / redis / httpx / requests`。
- 无装饰器 `@router / @app.route / @command`。
- 函数纯计算（无 I/O、无外部调用、无副作用），圈复杂度可校验。

**场景示例**：数据清洗、报表聚合、字符串/日期工具、纯函数辅助。

### 1.2 L1 中风险（架构 + 用例审核，不审源码）
- 普通业务 CRUD、非核心流程、常规读写、页面展示逻辑。
- 涉及 DB 读写但不在核心交易链路。
- 自动特征：命中 service/model 层但路径不含 `payment/refund/order/settle/auth/permission`。

### 1.3 L2 高风险（强制双人逐行 + 灰度）
**任一命中即 L2**：
- 路径或符号含：`payment refund settle order auth login permission token crypto encrypt decrypt webhooks alipay wechatpay`。
- 涉及用户鉴权、权限管控、隐私加密、资金交易、第三方安全对接、核心架构（基类/中间件/网关）。
- 改动 `.env / config / docker-compose / CI 配置 / 迁移脚本（含数据回填）`。

### 1.4 上下文敏感（环境维度）
- 同一函数在生产环境默认 L2，在测试环境可降一级（仅用于本地验证，不阻断流水线）。
- `risk-classify.sh` 读 `APP_ENV` / git 分支：`main/master/prod` → 保守；`dev/test/feature/*` → 放宽。

## 2. AI 编码强制四阶段流水线（叠加分级路由）

### 2.1 需求规格化（前置拦截）
- 禁止纯自然语言直接生成代码。
- 必须填写 `.ai-templates/structured-requirement.md`（输入输出、边界、异常、性能、安全、测试用例）。
- 复杂业务（L1/L2）必须附带 Gherkin 可执行场景规约（`.ai-requirement.feature`）。
- **灰区处理**（关键修正）：AI 无法判定需求是否足够结构化时，输出 `confidence: low` 并**回退人工确认**，而非简单返回错误码后无限重试。
- 未填结构化需求 → 终止生成，返回 `[REQ-NOT-STRUCTURED]` 错误。

### 2.2 基础编码（架构约束绑定）
- 严格匹配 `.ai-rules.md` 分层规范与 profile 依赖规则。
- 自动拦截跨层调用、违规依赖、非法资源引用（由 `quality-gate.sh` 的架构 lint 段执行）。
- 仅用公司授权模型生成代码；核心代码（L2）禁止私有模型输出。

### 2.3 重构优化（自动质量提纯）
- 自动去冗余、去重复、统一风格、精简逻辑。
- 压缩技术债务，消除无效判断与空逻辑。

### 2.4 分级终审路由
- **L0**：全部门禁通过 → 自动放行。
- **L1**：门禁通过 → 进入【架构 + 用例评审】队列（不审源码）。
- **L2**：门禁通过 → 强制【双人源码 Review + 安全终审 + 灰度发布】。
- **关键修正**：L0/L1 默认不强制逐行审核，但**允许人工主动触发**（规范不得堵死人工介入口子）。

## 3. 质量门禁硬阈值（`quality-gate.sh` 强制校验）

所有等级必须全部通过；任意不达标直接废弃/重试，禁止放行。

### 3.1 测试覆盖率（差异化阈值，避免凑数）
| 维度 | L0 | L1 | L2 |
| --- | --- | --- | --- |
| 核心业务模块行覆盖 | ≥ 85% | ≥ 90% | ≥ 95% |
| 分支覆盖 | ≥ 80% | ≥ 85% | ≥ 90% |
| 辅助/工具类 | ≥ 70% | ≥ 80% | ≥ 85% |

- Gherkin 场景：正常 + 异常 + 边界全覆盖（L1/L2 强制）。
- **关键修正**：覆盖率不达标时，**优先用变异测试（mutation score）补判**——变异分数 ≥ 80% 可豁免 5% 覆盖率缺口，避免为凑覆盖率写空 assert。

### 3.2 代码质量
- 单函数圈复杂度 ≤ **15**（默认门禁；领域豁免：规则引擎/状态机/解析器 ≤ 20，需 PR 标注不可拆分理由）。*（修正：原 ≤10 过严逼迫无意义拆层）*
- 代码重复率 ≤ 5%。
- 单函数 ≤ 80 行，嵌套 ≤ 3 层。
- 无未捕获异常、无资源泄漏、无死循环、无无效依赖。

### 3.3 安全与合规
- SAST 高危漏洞 = **0**（误报需走「修复 / 误报豁免」二选一闭环记录，禁止直接静默压制）。
- 开源版权检测：无侵权、无许可证冲突。
- 架构合规：无违规分层、无非法数据流转。

### 3.4 重试与升级（关键修正：防烧 token）
- 门禁失败重试上限 `MAX_RETRY=3`。
- 超限 → 自动转人工，AI 停止生成，输出失败快照（diff + 失败指标 + 已尝试方案）。

## 4. 分级发布通路（机器路由）

### 4.1 L0 自动通路（有条件）
结构化需求 → AI 生成 → 自动重构 → 全门禁通过 → **变异测试分数 ≥ 80%** → 直接交付 → 归档质量报表。
> 若变异分数不达标：降级为"建议抽审"，不阻断但提醒测试覆盖有洞（逻辑缺陷门禁抓不到）。

### 4.2 L1 半自动通路
结构化需求 → AI 生成 → 自动重构 → 全门禁通过 → 【架构 + 用例评审】→ 通过后交付部署。
机器仅推送测试与架构评审单据，不推逐行源码评审。

### 4.3 L2 全管控通路
结构化需求 → AI 生成 → 自动重构 → 全门禁通过 → 双人源码 Review → 安全终审 → 灰度发布 → 正式上线。

## 5. AI 强制禁止规则（触发即拦截）
- 禁止无风险定级直接生成业务代码（必须先跑 `risk-classify.sh` 或人工标注）。
- 禁止绕过任意自动化质量门禁输出代码。
- 禁止 L2 跳过双人复核与灰度流程（双人复核凭证: review-token，不可伪造）。
- 禁止需求未结构化、无约束规约时生成业务逻辑代码。
- 禁止输出违反架构、安全、依赖规范的代码片段。
- 禁止 AI 自评风险等级（必须静态推断或人工标注）。
- 禁止无限重试（超 `MAX_RETRY=3` 必须转人工）。

> 注：原规范"禁止 L0/L1 主动申请人工逐行审核"已删除——人工主动介入是安全正向行为，不应堵死。

---

## 6. AI 输出范式
- 不追求代码行数，追求**可测试、低复杂度、高合规**。
- 优先适配自动化测试体系，所有业务逻辑可被单元测试 + 场景测试覆盖。
- 输出默认轻量、无冗余、无隐性埋点、无私有逻辑。
- 自动留存：生成日志、约束参数、测试适配说明、质量指标快照（写入 `.ai-governance/reports/`）。

---

## 7. 落地机制
- `risk-classify.sh`：对暂存改动逐文件输出风险等级 + 依据。
- `quality-gate.sh`：按等级跑差异化门禁，输出通过/失败报告。
- `ai-guard.sh`（增强）：调用上述两脚本，按等级路由（L0 放行 / L1 标记评审 / L2 阻断提交待人工）。
- 所有报告归档 `.ai-governance/reports/<timestamp>.md`，可追溯。
